# ADR-0010: 類型の統合（「専門集積型」への畳み込み）

- ステータス: Accepted
- 日付: 2026-06-19

## コンテキスト

駅をサブエージェントで量産する過程で、類型（L2・ADR-0002）が15種まで膨らみ、保留中の提案（物流団地型/空港ターミナル型/老舗食集積型/ライブハウス・音楽集積型/相撲・興行集積型/観光・行楽地型/レジャー・興行集積型/工場跡転換型/下町商店街型 …）がさらに溜まった。

これらの多くは「**特定産業 X が面的に集積した街**」という同じメタパターンの変種で、放置すると駅を足すたびに新類型が増えて発散する。一方、**「どの産業か」は既に 需要タグ・アンカータグで表現されている**（例: サブカル集積型 ＝ アンカー[闇市/問屋] × 需要[サブカル]）。類型側にも産業名を持つのは二重表現。

## 決定

1. **新類型 `専門集積型` を導入**し、「特定の産業・専門が面的に集積した街」を1語に畳む。**どの産業かは 需要/アンカー タグで表す**（ADR-0005 の「richnessは本文・タグ、型はフラット」と一貫）。
2. 次の5類型を `専門集積型` に統合（移行）する：
   `サブカル集積型` / `古書店街型` / `専門卸街型` / `町工場集積型` / `大工場・産業発祥型`。
3. **残す類型**（畳まない）: `門前町型`・`大学集積型`・`闇市あがり型`・`ターミナル商業型`・`住宅地型`・`官庁街型`・`興行・歓楽街型`・`オフィス街型`・`ブランド商店街型`・`クリエイティブ転換型`。
4. 保留中の類型提案は**追加せず** `専門集積型` または既存型＋タグで表す（物流団地型→専門集積型＋需要[物流・倉庫業務]、空港ターミナル型→ターミナル商業型＋アンカー[空港]、老舗食集積型→興行・歓楽街型 or 専門集積型＋需要[食] 等）。
5. ショックの「再開発の下位種」提案（国際都心化/計画的副都心開発/臨海部・ウォーターフロント開発）も**追加せず** `大規模再開発` に集約。`都市計画道路の貫通` は `区画整理・用途地域` で表す。

結果として 類型は **15種 → 11種** に収れんする。

## 根拠

- **二重表現の排除**: 「産業名つき集積型」は アンカー×需要 から導出できる冗長。型は「街の形（shape）」だけを担い、産業は別軸に置く方が、ADR-0005 のフラットタグ思想と一貫する。
- **発散の停止**: 駅を足すたびに「○○集積型」が増える構造を断つ。新しい専門産業が来ても `専門集積型` ＋ 需要タグで吸収できる。
- **横断クエリは維持できる**: 「サブカルの街」を見たければ `需要=サブカル`、「専門産業に特化した街」を見たければ `類型=専門集積型` で絞れる。両軸の掛け合わせでむしろ自由度が上がる。

### なぜ `大学集積型` は残すか

`大学・学校` は単なる一産業でなく、街全体の生態系（学生・古書・楽器・安い食・住・予備校）を生むほど強い**機関アンカー**であり、ADR-0002 の創設例でもある。「専門産業の集積」とは挙動が異なるため、例外的に独立類型として残す（`大学集積型 = アンカー[大学・学校]` と対応）。

## 結果

- (+) 類型が締まり、以後の駅追加で発散しない。型＝形、産業＝需要/アンカー、と役割が明確化。
- (+) `専門集積型 × 需要` の掛け合わせで、より柔軟な横断分析ができる。
- (−) 「古書店街型」等の語感の鋭さは型レベルでは失う（本文と需要タグで補う）。
- (−) 既存データの一括移行（ローカルJSON＋Notion全駅）と patterns.md の更新が必要。

## 移行

- `data/vocab.ts` の `ARCHETYPES` を更新（5種削除・`専門集積型` 追加）。
- `data/stations/*.json` と Notion 全111ページの `類型` を一括置換（5種→専門集積型・重複除去）。`scripts/` の移行スクリプトで実施。
- Notion スキーマから旧5オプションを除去（`ALTER COLUMN SET`）。
- `docs/patterns.md` の類型分布を更新。

## 検討した代替案

- **個別型を残す**: 語感は鋭いが、駅追加のたびに発散し、産業名を型と需要で二重に持つ冗長が残るため却下。
- **大学集積型も畳む**: 一貫性は上がるが、機関アンカーの別格性と創設例の重みを考え、例外として残した。
