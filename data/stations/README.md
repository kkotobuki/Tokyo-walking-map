# data/stations/ — 駅データ（ローカル先行）

1駅 = 1ファイル `<駅名>.json`。`scripts/import-stations.ts` がここを読んで Notion へ一括投入する（ADR-0009）。
**Notion へ直接書かず、まずここに JSON を書く**のが原則（トークン効率＋語彙の一貫性のため）。

## スキーマ（`data/vocab.ts` の `StationRecord` と一致）

```json
{
  "駅名": "渋谷",
  "区": "渋谷区",
  "カテゴリ": "IT",
  "路線": ["JR山手線", "東京メトロ銀座線"],
  "アンカー": ["鉄道ターミナル", "計画型(財閥/地主開発)"],
  "ショック": ["戦災+闇市", "大規模再開発"],
  "需要": ["サブカル", "買い物", "IT・スタートアップ"],
  "類型": ["ターミナル商業型", "オフィス街型"],
  "ズレ類型": ["供給の慣性で残った床に新需要"],
  "観察お題": "…①現在の風景＋問い。答えは言わない。末尾に『今 成長/成熟/衰退/転換 のどれだと思う？』",
  "お題の解説": "…①の問いへの直接の答え（今どのフェーズか・なぜか）",
  "供給の筋": "…③ 街が用意してきた床/立地/インフラの来歴（ゆっくり動く側）",
  "需要の筋": "…③ 来る人が求めたものの変遷（速く動く側）",
  "ズレ": "…④ 供給と需要の食い違い＝この街の正体。予兆の読み方も",
  "未来の観点": "…⑤ 答えを出さず、①仮想ショック注入 ②需給ギャップに何がハマるか の2問",
  "proposedNewOptions": [
    { "field": "需要", "name": "コーヒー・カフェ", "reason": "食では粒度が粗い" }
  ]
}
```

## 書くときのルール

- タグ（アンカー/ショック/需要/類型/ズレ類型/路線/カテゴリ）は **`data/vocab.ts` にある値のみ**使う。
- 無い概念は、最も近い既存値を使ったうえで `proposedNewOptions` に記録する（import が警告として集計）。
- 本文6項目は合計 **3000字以内**（ADR-0005）。骨格は ADR-0006（①観察お題 ②賭けはアプリ側 ③供給/需要の筋 ④ズレ ⑤未来の観点）。
- 確信のない年号・固有名は断定しない。
- 値は日本語を直接書く（エスケープ不要。JSON として正しければよい）。
